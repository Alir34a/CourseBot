## باگ‌های حین تست و فیکس‌شده
1. `completion_rate` روی GROUP-BY خالی → شمارش تکمیل آخرین اپیزود.
2. CSRF سشن خالی (دوره وب، حالا حذف شده).
3. کانکشن باز در backup/restore → close + retry.
4. `inline_keyboard` تاپل است (۲ بار، در منوی کاربر و فوتر) → بازسازی Markup.
5. `delete_course` ترتیب detach را رعایت نمی‌کرد (FK روی users.current_course) → detach اول، حذف بعد.
6. ویس/video_note نوع جدا از audio/video هستند و گرفته نمی‌شدند → kinds جدید + پخش + تست هر ۶ نوع.
7. نمایش جزئیات اپیزود ادمین به متغیر تعریف‌نشده ارجاع می‌داد → بازنویسی نما.
8. مدیای تنها بدون دکمه می‌ماند → دکمه همیشه روی آخرین پیام + `senders` تنبل.
9. دکمهٔ اپیزودِ حذف‌شده بی‌صدا `return` می‌کرد → query بی‌پاسخ، spinner تا تایم‌اوت → alert + `safe_edit_markup`.
10. دابل‌تپ «منو» (و ۲۰ صفحهٔ پنل) خطای «Message is not modified» می‌داد → ۱ از ۲۳ جا هندل می‌کرد → `safe_edit` مشترک.
11. `show_menu` بدون try/except بود؛ دابل‌تپ به کاربر «خطای عمومی» نشان می‌داد.
12. `validate_callback` سقف ۱۲۰ داشت ولی حد واقعی تلگرام ۶۴ بایت است → اصلاح + تست.
13. کارت آفر راه برگشت نداشت (بن‌بست) → دکمهٔ «🏠 منو».
14. لینک خرید دائمی در چت می‌ماند → TTL با `job_queue`.
15. منوهای تکراری انباشته می‌شدند (هر «منو» از روی اپیزود یک نسخهٔ تازه می‌ساخت) → `modules/screens`.
16. `_course_finished` تنها نمای منو‌مانده روی `reply_text` بود → هر بار باز کردن اپیزود آخر یک «تبریک» تازه می‌ساخت → `render`.
17. جشن تکراری: `s['finished']` بعد از تکمیل گرفته می‌شد و «قبلاً تمام شده بود» را نمی‌دانست → `was_finished` قبل از تکمیل + ادغام آفر در همان صفحه.
18. `catalog_progress` و برچسب دکمه‌ها اصلاً در `texts.py` نبودند → دو صفحهٔ اصلی (منو و اپیزود) هیچ متن قابل‌ویرایشی نداشتند → انتقال به `texts.py` + `TEXT_DEFS`.
19. `settings.delete` هیچ‌جا استفاده نمی‌شد → ۱۵ متن قابل‌ویرایش بدون هیچ راه برگشتی → `reset_text` + دکمهٔ ↩️.
20. `show_menu` برای دورهٔ تمام‌شده عنوان خود را با «تبریک» عوض می‌کرد → هر بار «🏠 منو» یعنی یک جشن دیگر، و نام دوره گم می‌شد → منو، منو می‌ماند.
16. **دابل‌های تست**: ۵ نسخهٔ کپی‌شده، بدون `message_id` و بدون خطای واقعی تلگرام → `tests/doubles.py` مشترک با `message_id` یکتا و خطای وفادارانه. اولین تستی که این را ثابت کرد: «ادمین با دابل‌تپ تنبیه نشود».
17. **تستی که الکی سبز بود**: assertِ «بدون خطا» دنبال کلمهٔ `خطا` می‌گشت، ولی متن خطای عمومی «مشکلی پیش اومد» است → به «هیچ toast/alertی داده نشده» تغییر کرد (با mutation test راستی‌آزمایی شد).
